## Manual / visual
- `tools\screenshot.py` (native Windows platform, throwaway data root with **SYNTHETIC**-labelled
  cases and programmatically generated geometric images): Dashboard, Cases, Evidence (Overview,
  Image properties, Integrity & history), Settings, About and New-case dialog in light and dark
  themes. Real `data\` folder untouched.
- Problems found during visual inspection and fixed before final test run:
  1. Unbroken 64-char SHA-256 labels forced the details scroll viewport too wide, clipping the
     thumbnail, Copy button and Integrity fields. Replaced with read-only `QLineEdit` fields so
     hashes stay selectable/copyable without overflowing.
  2. Evidence table column 1 ("Original filename") was squished by `ResizeToContents` on the
     timestamp column. Switched to sensible interactive column widths and balanced splitter sizes.
  3. `"Integrity & history"` tab title rendered as `"Integrity _history"` because Qt treats `&` as
     a mnemonic prefix. Escaped to `"Integrity && history"`.
  4. `MainWindow.navigate_index` skipped `refresh()` when already on the target row (stale
     Dashboard). Now refreshes even when re-selecting the active row.
  5. Settings import-limit spinboxes stretched across the entire card; constrained to 130 px.
- `start.bat` smoke-launched against a throwaway `IMAGETRACE_DATA_ROOT` (`pythonw.exe`, schema v2
  migrated, `import PySide6, PIL` check passed).
